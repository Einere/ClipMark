# ClipMark 재단장 디자인

작성일: 2026-10-02
상태: Tauri 기반 첫 구현 완료. macOS 13 이상 및 Windows/Linux를 유지한다. 최종 검증과 제한은 [구현 기록](./superpowers/plans/2026-10-02-clipmark-redesign-ledger.md)을 참조한다.

## 제품 목표와 우선순위

ClipMark는 가장 간편하고 우아한 Markdown 파일 편집기를 지향한다. 웹 콘텐츠 보관은 제품의 출발점이며, 클리핑에서 편집으로 이어지는 연속성은 계속 핵심 가치로 유지한다.

1. 조용하고 우아한 화면과 자연스러운 사용 경험.
2. 빠르고 안정적이며 예측 가능한 편집 동작.
3. Apple 생태계에 최적화된 앱 구조 검토. 실제 Apple Liquid Glass 적용은 첫 재단장의 필수 조건이며 CSS 유사 효과로 대체하지 않는다.

전체 네이티브 전환은 후순위다. 현재 Tauri 기반의 사용자 체감 성능과 React 상태·이펙트 관리 부담은 구분하여 평가한다. 격리된 Tauri 앱에서 실제 Liquid Glass 하단 조작부의 배치·클릭·크기 조절·편집 포커스를 확인했다. Tauri 유지 + 일부 네이티브 조작부가 가능한 후보이며 최종 어댑터 방식은 구현 계획에서 정한다. 상세 근거와 제약은 [실행 검증](./LIQUID_GLASS_SPIKE.md)에 기록한다.

## 문서와 창

현재 Tauri 재단장 버전은 기존 macOS 13 이상 및 Windows/Linux 지원을 유지한다. 실제 Apple Liquid Glass는 macOS 26 이상에서 사용하고, 이전 macOS에서는 일반 네이티브 버튼을 사용한다. macOS 26 이상으로 지원 범위를 좁히는 결정은 2차 Apple 네이티브 전환에서 검토한다.

- 파일 하나에 편집창 하나를 유지한다. 미리보기는 같은 문서에 연결된 보조 창이다.
- 원문 편집을 기본으로 한다. 입력 중 문법의 완성 여부 때문에 글자 크기나 행 높이가 바뀌는 편집 방식은 채택하지 않는다.
- 사용자가 원하면 단축키 또는 플로팅 버튼으로 별도 미리보기 창을 연다. 두 창은 각각 이동·크기 조절이 가능하다.
- 이번 첫 구현 범위에는 분할 미리보기, 탭, 라이브러리, 젠 모드를 포함하지 않는다. 젠 모드는 필수 요구사항이 아닌 추후 선택 후보다.

미리보기를 닫아도 편집은 계속하고, 편집창이 실제로 닫히면 연결된 미리보기도 닫는다. 저장하지 않은 변경 때문에 닫기를 취소하면 두 창을 유지한다. 미리보기는 열 때마다 기본 크기의 새 창으로 생성한다. 이전 위치·크기를 기억하거나 복원하지 않는다.

### 미리보기 최초 배치

미리보기는 편집창과 겹치지 않게 옆에 연다. 다른 앱의 창이나 화면의 빈 공간은 탐지하지 않는다. 편집창의 위치·크기와 화면 작업 영역만 기준으로 오른쪽 배치를 우선하고, 오른쪽에 들어가지 않으면 왼쪽 등 다른 방향을 확인한다. 두 창 사이에 간격을 둔다. 편집창을 자동으로 이동하거나 줄이지 않는다. 사용자가 연 뒤에는 자유롭게 배치한다.

편집창이 화면 작업 영역 전체를 차지하면 같은 화면 안에서 두 창을 겹치지 않게 배치할 수 없다. 첫 구현은 현재 화면에서 최소 겹침 위치에 열며 부모 크기를 바꾸지 않는다. 일반적인 열기 흐름에 빈 공간 탐지나 공간 부족 안내를 추가하지 않는다. 전체 화면·Spaces·다중 모니터는 추가 수동 검증이 필요하다.

### 파일명과 저장

편집 본문 위에 별도 제목 표시·편집 영역을 두지 않는다. 파일명과 변경 여부는 macOS 창 제목으로 확인한다. 다른 이름이 필요하면 기존 ⇧⌘S로 다른 이름으로 저장한다. 이 동작은 새 경로에 현재 내용을 저장하며 원본 파일을 이동하거나 이름을 변경하지 않는다.

미리보기 토글은 기존 ⌥⌘P를 유지한다. 편집창에서 열 때 편집 포커스를 유지한다. 편집창과 미리보기 양쪽에서 토글할 수 있으며, 미리보기에서 닫으면 연결된 편집창의 원문으로 포커스를 돌린다. 기존 경로 복사 ⌥⌘C와 목차 토글 ⌥⌘T도 유지한다.

## 미리보기와 편집의 연속성

- 저장 전 변경을 포함한 현재 문서를 미리보기에 반영한다.
- 편집창에서 커서를 이동하거나 입력하면 해당 원문 위치에 대응하는 미리보기 블록을 따라간다.
- 대상이 이미 적절한 가시 영역에 있으면 불필요하게 스크롤하지 않는다. 같은 블록 안의 커서 이동으로 매번 화면을 움직이지 않는다.
- 사용자가 미리보기를 직접 스크롤하면 자동 추적을 중단한다. 시간 경과만으로 추적을 재개하지 않는다.
- 편집창에서 다시 커서를 옮기거나 입력하면 추적을 재개한다. 포커스 변경만으로 미리보기 위치를 바꾸지 않는다.
- 미리보기 조작은 편집창의 커서와 스크롤 위치를 움직이지 않는다.

원문 행과 미리보기 블록을 연결한다. 수동 스크롤 이후에는 시간이 지나거나 창에 포커스만 돌아와도 추적을 재개하지 않는다. 커서 이동 또는 입력으로 편집을 재개하면 다시 추적한다.

## 공통 룩앤필과 역할별 표현

두 창은 배경·본문색·강조색·창 표현과 간격의 리듬을 공유한다. 편집과 읽기에 필요한 표현은 구분한다.

### 편집창

- 고정폭 글꼴, 은은한 Markdown 문법 색상, 편안한 행간과 여백.
- 줄 번호를 유지하고 본문보다 낮은 시각적 비중으로 표시한다.
- 원문 문법을 편집해도 타이포그래피의 크기와 행 높이는 안정적으로 유지한다.
- 본문 최대 폭을 제한하지 않는다. 창 크기에 따라 편집 영역이 확장된다.
- 파일명과 저장 상태는 macOS 창 제목으로 표시하며 본문 위에 중복 표시하지 않는다.

### 미리보기 창

- 읽기용 본문 글꼴과 정돈된 아티클 같은 표현.
- 제목 위계, 문단 간격, 강조, 취소선, 인용, 목록을 명확히 구분한다.
- 편집창과 다른 글꼴을 사용해도 공통 색상과 간격으로 통일감을 유지한다.
- Mac 창 제어는 좌상단에 둔다. 우상단에 중복 닫기 버튼을 추가하지 않는다.

미리보기도 본문 최대 폭을 제한하지 않는다. 사용자가 창 크기로 읽기 폭을 조절하고 양쪽 여백은 유지한다. 구체적인 글꼴 이름·크기·행간·색상값은 실제 화면 검토에서 확정한다.

### 목차

목차는 계속 펼쳐두고 문서 구조를 보는 용도로, 편집창 내부의 접이식 사이드 패널을 유지한다. ⌥⌘T로 토글하며 현재 제목을 표시한다. 제목 선택 시 원문으로 이동하고 열린 미리보기도 따라간다. 별도 목차 창이나 일시적인 팝오버로 변경하지 않는다.

`CONTENTS` 헤더 없이 바로 제목 목록을 표시한다. 최소 폭은 176px이며 고정 최대 폭은 두지 않는다. 창 안에서 본문 최소 공간과 조절 바 공간은 유지한다.

목차 구분선은 평소 숨기고 조절 영역 hover·키보드 focus·드래그 중에만 표시한다. 조절 영역의 폭과 접근성 separator는 그대로 유지한다.

## 하단 코너 플로팅 조작부

긴 고정 툴바 대신 콘텐츠와 구분되는 작은 조작 그룹을 사용한다. 사용자가 임의로 드래그해서 재배치하는 기능은 요구하지 않는다.

- 좌하단: 파일 경로를 표시하는 복사 버튼.
- 우하단: 별도 미리보기 창 토글 버튼.
- 미리보기 버튼은 위치와 크기를 유지한다. 경로 영역은 버튼과 간격을 확보한 남은 공간까지만 확장한다.
- 긴 경로는 말줄임한다. 폴더 부분을 먼저 축약하고, 파일명 자체가 길면 파일명도 줄이는 것이 목표다.
- 경로 버튼 클릭 시 표시 문자열이 아닌 전체 경로를 복사한다.
- 마우스 호버나 키보드 포커스에 따른 전체 경로 툴팁은 추가하지 않는다.
- 작업 영역 전체 하단에 76px을 확보한다. 본문·목차·조절 바·검색 패널이 조작부와 겹치지 않는다. 조작부는 44pt 높이와 하단 16pt 여백을 유지한다.

창 전체의 미색 배경을 하나로 연결하여 안전 공간을 별도 푸터로 구획하지 않는다. 검색·치환은 ⌘F 때 편집 영역 상단에 나타나는 작은 임시 패널로 정돈한다. 검색 패널은 기존 CodeMirror 기능을 사용하며 Liquid Glass 재질은 네이티브 하단 조작부에 적용한다. Apple의 edge-to-edge 콘텐츠 방향을 따르되 AppKit scroll edge effect를 웹 편집기에 적용한 것으로 표현하지 않는다.
- 키보드 접근과 명확한 접근성 이름을 유지한다.

실제 Apple Liquid Glass를 본문 위의 독립된 네이티브 조작 계층에 사용한다. 본문은 안정적인 배경을 유지한다. HTML 시안은 배치 참고용이며 실제 재질의 디자인 검증 자료로 취급하지 않는다. 격리 앱에서는 실제 재질을 확인했으며, 제품 적용에서는 문서 창별 연결과 조작부 표현·접근성을 추가 검증한다.

Apple 공식 안내: https://developer.apple.com/design/human-interface-guidelines/materials

## 클리핑 원칙

기사·뉴스·아티클·제품 홈페이지·다른 앱 등 다양한 출처를 다룬다. 특정 서비스에만 최적화하지 않는다.

- Markdown으로 표현 가능한 제목·강조·취소선·링크·목록·인용·코드·표 등의 의미와 구조를 최대한 유지한다.
- Markdown으로 표현할 수 없고 변환하면 의미가 손실되는 요소는 제한된 HTML로 보존한다. 위첨자·아래첨자가 예시다.
- 원본 CSS와 스타일은 가져오지 않는다.
- 허용할 HTML 태그와 속성은 실제 복사 사례와 현재 변환·렌더링 정책을 검토해서 정한다. 스크립트·이벤트 속성 등 실행 가능한 콘텐츠는 허용하지 않는다.
- 보존할 수 없는 표현은 내용과 읽는 순서를 최대한 유지하는 방향으로 정리한다.

클리핑 정책은 이번 시각 리디자인과 독립된 후속 구현 범위다. 이번 문서에서 모든 HTML 변환 규칙이 확정된 것으로 취급하지 않는다.

## 첫 구현 범위 제안

Tauri 기반을 유지한 채 다음 두 단계로 진행하는 것을 제안한다.

1. 공통 룩앤필, 원문 편집의 시각적 안정성, 줄 번호, 최대 폭 없는 본문, 내부 목차, 실제 네이티브 Liquid Glass 하단 조작부와 긴 경로 처리.
2. 별도 미리보기 창과 비겹침 최초 배치, 문서·커서 상태 연결, 사용자 행동 기준 추적 중단·재개.

현재 문서 세션·편집기·미리보기 렌더링과 원문 위치 매핑을 재사용한다. Rust가 관리하는 창 연결과 창별 이벤트로 읽기 전용 스냅샷을 전달하며 connection ID와 증가하는 sequence로 오래된 결과를 제외한다. 닫힌 미리보기 창은 보관하지 않는다. 편집 세션이 최신 문서를 유지하고, 새 미리보기를 열면 최신 내용과 현재 커서 위치를 전달한다. 이전 미리보기의 수동 스크롤 위치도 복원하지 않는다.

파일 저장과 변경 상태의 기준은 편집 문서 세션 하나로 유지한다. 미리보기는 표시를 위한 읽기 전용 상태를 전달받으며 독립된 편집·저장 세션을 만들지 않는다. 창 간 연결 실패 시 편집·저장 기능은 유지하고, 미리보기에서 오래된 내용이 최신 내용처럼 표시되지 않도록 한다.

## 검증 기준

- 긴 경로, 좁고 넓은 창, 긴 원문 줄에서 버튼 겹침·가림 없이 동작한다.
- 문법 기호를 지워도 편집창의 글자 크기와 행 높이가 변하지 않는다.
- 미리보기 토글이 편집 커서와 입력 포커스를 불필요하게 잃게 하지 않는다.
- 저장하지 않은 변경이 미리보기에 반영되고 문서 간 상태가 섞이지 않는다.
- 수동으로 미리보기를 읽는 동안 시간이 지나도 위치가 돌아가지 않는다.
- 편집 재개 시 해당 블록을 따라가되 이미 보이는 부분은 불필요하게 움직이지 않는다.
- 실제 macOS에서 별도 창 이동·크기 조절·닫기와 단축키 흐름을 확인한다.
- 다른 이름으로 저장의 취소·실패·새 문서 첫 저장에서 내용 손실이나 잘못된 경로가 발생하지 않는다.
- 다른 이름으로 저장 뒤 경로 복사와 같은 파일 다시 열기가 저장된 경로를 기준으로 동작한다.
- 미리보기 최초 배치가 편집창을 가리지 않으며, 화면 가장자리·공간 부족·전체 화면에서 확정한 정책을 따른다.
- 편집창 닫기를 취소하면 연결된 미리보기와 저장 전 내용이 유지된다.
- 시각 변경만을 위한 테스트는 늘리지 않는다. 창 생명주기·상태 연결·추적 전환 등 동작 변경은 기존 테스트를 활용하거나 최소한의 회귀 검증을 추가한다.

## 첫 구현에서 확정한 사항

1. 기존 objc2 의존성으로 문서 창별 NSGlassEffectView와 NSButton을 연결한다. 새 플러그인 의존성은 추가하지 않는다.
2. 편집창 기본 960×720, 미리보기 기본 640×720, 창 사이 간격 12pt. 현재 화면에서 오른쪽·왼쪽·아래·위 순서로 비겹침 배치를 찾는다. 불가능하면 최소 겹침으로 열며 부모 크기는 바꾸지 않는다.
3. 원문은 14px 고정폭 글꼴과 일정한 행간을 유지한다. 하단 조작부는 높이 44pt, 가장자리 여백 16pt이며 경로는 가운데 말줄임으로 버튼 영역을 보장한다.
4. 최소 지원 macOS 13.0을 유지하며 26 미만에서는 일반 버튼으로 대체한다. 구버전 OS, 다중 모니터·Spaces·전체 화면과 보조 기술의 종합 검증은 남아 있다.

HTML 허용 목록, 전체 네이티브 전환, 젠 모드, 본문 폭 제한 옵션은 후속 범위에서 결정한다.

## 문서 리뷰 결과

2026-10-02 검토. 방향은 일관되며 아래 충돌과 누락을 보완했다.

- 새 미리보기 창 생성과 숨겨진 창 상태 보관이 충돌했다. 닫힌 창을 보관하지 않고 최신 편집 상태로 새로 여는 것으로 통일했다.
- 편집창 닫기 취소 시 보조 창까지 닫힐 가능성을 제거했다. 실제 닫기 완료에만 미리보기를 닫는다.
- 파일명 수정은 기존 다른 이름으로 저장 흐름만으로 충족되지 않는다. 실제 이름 변경, 저장 전 내용 보존, 실패와 충돌 처리, 문서 경로 등록 갱신을 명시했다.
- 미리보기 최초 배치는 다른 앱을 조사하지 않고 편집창의 사각형과 화면 작업 영역만 기준으로 계산한다. 편집창이 화면 전체를 차지하는 예외는 구현 계획에서 다룬다.
- 실제 Liquid Glass의 Tauri 실행 가능성은 격리 앱에서 확인했다. 기존 편집기 통합과 문서 창별 네이티브 이벤트 연결은 아직 제품 검증이 필요하다.

첫 구현은 Tauri를 유지하면서 실제 AppKit Liquid Glass 조작부를 적용한다. 별도 미리보기와 저장 동작의 실제 실행 결과, 리뷰 수정 사항은 구현 기록에 남긴다. 이후 사용자 피드백으로 인라인 파일명 수정은 제거하고 기존 Save As 흐름으로 통일했다.
