# ClipMark 색상·디자인 리뷰 — 2026-10-06

## 결론

현재 미색 팔레트와 조용한 편집 화면은 유지할 만하다. 전체 리디자인이나 배경을 더 하얗게 만드는 작업보다 상태별 대비와 환영 화면의 위계를 정돈하는 편이 효과가 크다. 확정한 개선점은 P2 네 건이며, 이번 리뷰 범위에서 P0/P1은 확인하지 않았다.

## 범위와 방법

- 기준: 현재 소스 `8ad0a00`, 설치된 `/Applications/ClipMark.app` v0.2.0.
- 독립 서브에이전트 세 명: 색상·타이포, 화면 위계·UX, 접근성·기술 감사. root가 실제 화면과 소스를 대조하고 중복 의견을 통합했다.
- 적용 스킬: `impeccable`의 product, critique, audit, colorize, typeset, layout, quieter, distill, clarify, adapt, harden 참조와 `web-design-guidelines`.
- 네이티브 환영 화면과 새 문서 편집 화면, 로컬 브라우저의 공유 미리보기 스타일을 관찰했다. 본문·제목·강조·취소선·링크·인용·목록·코드를 사용했다.
- 대비는 CSS OKLCH 및 color-mix를 linear sRGB 상대휘도로 환산한 계산값이다. AppKit 투명 재질은 아래 수치에 포함하지 않았다.
- 미색 유지, 최대 폭 제한 없음, 원문 편집과 별도 미리보기, 상시 목차, Apple Liquid Glass는 사용자 결정이다. 일반 디자인 가이드와 다르다는 이유로 결함으로 분류하지 않았다.
- 이번 작업은 리뷰다. 제품 코드 변경·커밋·배포는 하지 않았다.

## 유지할 요소

1. **배경과 읽기 대비.** 라이트 본문/배경 15.81:1, muted 8.95:1, soft 6.09:1. 다크 본문/배경 17.94:1. 미색 때문에 글이 흐리다는 근거는 없다. 기본 배경을 추가로 밝힐 필요는 낮다.
2. **한 캔버스로 연결된 목차와 본문.** 실제 설치 앱에서 배경과 낮은 강조의 활성 목차가 자연스럽게 연결된다. 상시 패널 경계가 시선을 끌지 않는다.
3. **역할별 타이포.** 원문 monospace와 읽기 미리보기의 sans가 같은 색상 체계를 공유하면서 편집·읽기 역할을 구분한다.
4. **조작부에 한정한 실제 Liquid Glass.** NSGlassEffectView를 사용하고 임의의 색상 유리를 덧씌우지 않는 방향이 맞다. 본문 전체로 재질을 확대할 이유는 없다.

## 우선 개선점

### 1. [P2] 일반 primary 버튼의 글자 대비

- 근거: `src/styles/components.css:90`, `src/styles/colors.css:158`, `src/components/dialog/UnsavedChangesDialog.tsx:44`.
- 라이트 3.95:1, 다크 3.08:1. 일반 14~15px 글자에 필요한 4.5:1에 못 미친다. 다크 active도 4.08:1이다.
- 환영 화면의 새 파일 버튼, 웹 저장 확인창의 Save 등 공유 Button에 해당한다. macOS 네이티브 Glass 버튼의 대비를 이 수치로 평가하지 않는다.
- 제안: primary의 글자·배경 조합만 조정하고 default/hover/active 모두 확인한다. 기존 solid accent 토큰을 먼저 활용한다.
- 해당 관점: colorize, audit, polish.

### 2. [P2] 라이트 테마의 포커스 표시가 희미함

- 근거: `src/styles/colors.css:102`, `src/styles/base.css:52`.
- focus ring/기본 배경 대비 약 1.81:1. 2px outline에 쓰이는 상태 표식이 배경과 충분히 구별되지 않는다.
- 단축키 중심 앱에서는 현재 조작 대상이 분명해야 한다. 화면 전체의 대비를 올릴 필요 없이 focus token을 진하게 만들면 된다.
- 제안: 실제 입력·버튼 주변 배경을 기준으로 3:1 이상 확보한다. 네이티브 AppKit focus 표시는 별도 실측 대상이다.
- 해당 관점: audit, colorize.

### 3. [P2] 미리보기 링크가 색에만 의존함

- 근거: `src/styles/components.css:950`.
- 기본 상태는 text-decoration:none, hover에서만 밑줄이 생긴다. 브라우저의 실제 computed style도 기본 밑줄 없음으로 확인했다.
- 링크 자체의 배경 대비는 충분하지만 링크와 주변 본문색 대비는 라이트 2.45:1, 다크 1.62:1이다. 색을 잘 구별하지 못하는 사용자는 링크 여부를 놓칠 수 있다.
- 제안: 기본 상태부터 가는 밑줄과 여유 있는 underline-offset을 제공한다. 링크의 파란색을 더 강하게 만드는 것보다 의미가 명확하다.
- 해당 관점: typeset, audit, polish.

### 4. [P2] 환영 화면이 편집 화면보다 홍보 페이지처럼 보임

- 근거: `src/components/welcome/WelcomeScreen.tsx:26`, `src/styles/components.css:345`.
- 큰 제목, 작은 대문자 소개, 긴 설명, 파란 강조 단어가 파일 선택보다 먼저 눈에 들어온다. 제목은 12ch 폭, 큰 fluid scale, -0.05em 자간을 사용한다.
- 실제 960×720 설치 앱에서 제목이 네 줄을 차지했고 최근 파일 일부는 아래로 밀렸다. 반복 사용자가 앱을 열 때의 주된 일은 소개 읽기보다 새 파일·열기·최근 파일 선택이다.
- 제안: 짧은 ClipMark 제목과 한 줄 안내로 줄이고 새 파일·열기·최근 파일을 중심에 둔다. 현재 미색과 작은 파란 accent를 유지한다.
- 해당 관점: quieter, distill, layout, clarify.

## 낮은 우선순위 및 미확정 항목

- **[P3] 미리보기 오류 문구:** `src/components/preview/PreviewWindow.tsx:33`, `:58`, `:75`. 포커스 조회·제목 변경 실패도 같은 error 상태를 통해 `Preview disconnected`로 표시한다. 연결 실패와 창 제어 실패를 구분하고 필요할 때 재열기 안내를 제공하면 더 정확하다. 이번 리뷰에서 실제 장애 주입은 하지 않았다.
- **긴 목차의 활성 항목 추적:** 활성 항목이 바뀌어도 목차를 그 위치로 스크롤하는 처리는 없다. 화면 밖의 활성 항목이 실제로 불편한지 긴 문서에서 추가 검증할 후보다. 사용자가 목차를 읽는 스크롤을 빼앗으면 안 된다.
- **수동 테마와 네이티브 재질:** DOM 테마와 AppKit appearance가 다른 상태에서 조작부가 이질적으로 보이는지 추가 확인할 후보다. 실제 재현하지 않았으므로 확정 문제에 포함하지 않았다.
- **창 폭에 따른 글자 크기:** UI·미리보기의 vw scale은 창 조절 시 글자 크기도 바꾼다. 고정 rem이 더 예측 가능할 수 있지만 현재 변화만으로 결함이라고 판단하지 않았다.

## 사용자 관점

- **단축키 중심 숙련 사용자:** 조용한 원문 화면과 별도 미리보기는 잘 맞는다. 포커스 표시를 강화하면 조작 대상을 더 빠르게 찾는다.
- **처음 사용하는 사람:** 파일 열기·새 파일보다 큰 소개 문구가 먼저 보인다. 환영 화면을 작업 중심으로 줄이면 첫 행동이 명확해진다.
- **색각·저시력 사용자:** 본문 대비는 좋다. 링크의 비색상 표식과 일반 버튼·포커스 대비가 개선 대상이다.

## 독립 탐지 결과와 한계

- Impeccable detector: 경고 1건, `src/styles/components.css:962` blockquote의 3px 왼쪽 선. 실제 인용 의미를 전달하는 표식이므로 장식용 side-stripe 규칙의 오탐으로 제외했다.
- 일반적인 AI 장식 패턴이 편집 화면을 지배하지 않는다. 환영 화면의 큰 홍보형 제목은 그 방향에 가까워 정돈이 필요하다. 미색과 Glass는 사용자 의도가 있으므로 자동으로 AI 패턴이라고 판정하지 않는다.
- 브라우저 evaluate가 read-only라 detector overlay 주입은 지원되지 않았다. 오버레이를 보여줬다고 주장하지 않는다. CLI detector, 실제 화면, computed style을 대체 근거로 사용했다.
- 네이티브 미리보기 전체·구형 macOS·Windows/Linux 실제 런타임·접근성 OS 설정 조합은 이번 리뷰에서 직접 검증하지 않았다. 웹 화면은 공유 스타일 관찰용이며 네이티브 창 배치를 증명하지 않는다.
- 임시 로컬 Vite 서버와 리뷰용 브라우저 탭은 종료했다. 제품 소스는 수정하지 않았다.

## 권장 순서

먼저 primary·focus·링크를 보완하고, 다음으로 환영 화면만 작게 정돈한다. 기본 미색 팔레트와 편집 화면 구조는 유지한다.
