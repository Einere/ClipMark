# 긴 문서 뷰포트 동기화 검증

2026-10-02, macOS의 별도 테스트 앱 ClipMarkRedesign에서 검증했다. 예제는 `/private/tmp/clipmark-long-sync.md`이며 574줄, 37개 제목으로 구성했다.

## 실제 앱에서 확인한 결과

- 긴 본문을 열면 상위·하위 제목 37개가 목차에 표시된다.
- 목차의 `09 · 긴 문서 탐색`을 선택하면 편집 커서가 해당 제목의 257번째 줄로 이동한다. 미리보기에도 같은 제목과 다음 문단이 보인다.
- 목차의 `18 · 최종 확인`을 선택한 뒤 미리보기를 열면 같은 제목과 다음 문단이 보인다.
- 9번 제목을 따라간 미리보기를 직접 스크롤하면 10번 구간까지 읽을 수 있다. 관찰 중에는 이전 커서 위치로 되돌아가지 않았다.
- `⌘↑`로 커서를 문서 시작에 이동하면 미리보기도 문서 제목과 첫 구간을 표시한다.
- 미리보기를 2번 구간으로 수동 스크롤한 뒤, 같은 파일을 열어 기존 편집창을 복원했다. 커서를 바꾸지 않고 포커스만 복귀한 상태에서는 미리보기의 수동 위치가 유지됐다. 이 과정에서 미리보기 창을 닫거나 다시 만들지 않았다.
- 이어서 `⌘↓`로 커서를 문서 끝에 이동하면 추적이 재개되고 미리보기에도 18번 구간 끝 표식이 보인다.
- 미리보기를 다시 17번 구간으로 수동 스크롤한 뒤, 편집창의 기존 끝 커서에서 입력하면 추적이 재개된다. 이후 `SYNC_RESUME_CHECK` 문구와 줄바꿈을 입력해 미리보기에 최신 문구가 반영되는 것도 확인했다. 테스트 입력은 저장하지 않았다.
- 편집창은 커서를 화면 안에 넣고, 미리보기는 해당 블록을 읽기 좋은 위치에 배치한다. 두 창의 제목이 같은 높이에 놓이는 방식은 아니다.

접근성 트리에는 화면 밖의 문단도 포함됐다. 따라서 실제 뷰포트 일치는 스크린샷으로 확인했다.

## 자동 검증

다음 명령의 4개 파일, 25개 테스트가 모두 통과했다.

```sh
npm run test -- src/components/preview/MarkdownPreview.test.tsx src/lib/preview-window-state.test.ts src/lib/toc.test.ts src/lib/editor-view-state-store.test.ts
```

여기에는 수동 스크롤 후 추적 중단, 다음 편집 동작에서 추적 재개, 포커스만 바뀔 때 추적을 재개하지 않는 동작이 포함된다.

## 창 전환 자동화 해결

처음에는 최소화된 편집창과 다른 문서 창 사이에서 자동화 입력 대상이 혼동됐다. 접근성 `Raise` 액션으로 입력 대상 창을 명시적으로 활성화하고, 같은 파일 열기로 기존 편집창을 복원해 해결했다. 미리보기를 계속 열어둔 상태의 수동 스크롤 → 포커스 복귀 → 커서 이동 또는 입력 전체 동선과 키보드의 문서 시작·끝 이동까지 실제 앱에서 확인했다. 확인한 범위에서 동기화 오류는 발견하지 않았으며 제품 코드 수정은 필요하지 않았다.
